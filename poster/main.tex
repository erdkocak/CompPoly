\begin{posterblock}{Motivation}
Polynomial multiplication is a core component of many cryptographic protocols, especially proof systems.
Evaluation and interpolation routines, polynomial commitments, and quotient-polynomial constructions all multiply polynomials repeatedly.
With the usual schoolbook algorithm, this is quadratic work. The NTT avoids direct convolution by evaluating both inputs on a root-of-unity domain, multiplying the values pointwise, and then transforming back.
Our Lean proof connects this executable pipeline to the algebraic specification, showing that the fast path is correct.
\vspace{0.9cm}

\end{posterblock}

\begin{posterblock}{Main Theorem}
\begin{lstlisting}[basicstyle=\ttfamily\normalsize]
theorem fastMulImpl_eq_mul
    (D : Domain R)
    (p q : CPolynomial R)
    (hfit : Domain.fits D p.val q.val) :
    fastMulImpl D p q = p * q
\end{lstlisting}

This is the public correctness statement for the multiplication implementation.
The precondition \leaninline{Domain.fits D p.val q.val} says that the selected NTT domain is large enough for the ordinary convolution, so the transform pipeline has no cyclic wraparound.
\end{posterblock}

\begin{posterblock}{Proof Graph Guide}
\raggedright
\footnotesize
\begin{enumerate}
\setlength{\itemsep}{0.2em}
\setlength{\parskip}{0.2em}
\item \texttt{fastMulImpl\_eq\_mul}: main theorem --- the NTT-based implementation equals canonical polynomial multiplication.
\item \texttt{fastMulImpl\_correct}: the executable multiplication pipeline agrees with the specification.
\item \texttt{fastMulSpec\_eq\_mul}: the specification computes the canonical polynomial product.
\item \textbf{Raw layer}: array-level correctness together with trimming and canonicalization lemmas.
\item \textbf{Forward / Inverse layer}: iterative radix-2 butterfly implementations realize the mathematical NTT and inverse NTT formulas.
\item \textbf{Coefficient layer}: coefficient-wise correctness follows from pointwise evaluation and inversion identities.
\item \textbf{Foundation layer}: inductive stage lemmas and root-of-unity orthogonality collapse the transform sums.
\end{enumerate}
\end{posterblock}
